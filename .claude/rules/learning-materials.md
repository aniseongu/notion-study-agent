# 강의자료 처리 규칙

## 출처 우선순위

1. 현재 사용자의 명시적 지시
2. 해당 과목의 live Notion `AI 활용 문서`(읽는 절차: [course-ai-docs.md](course-ai-docs.md))
3. 교수님 강의자료·활동지와 사용자가 지정한 원본
4. 사용자 필기·수업 TXT
5. 교재·친구 요약·외부 자료

2번은 자료를 **어떤 순서와 경계로 쓰는지**를 정하는 규칙이고, 3번 이하는 **내용 사실**의 원본이다(AGENTS.md 2절과
같은 원칙). 과목 문서가 더 구체적인 우선순위를 정하면 그것을 따른다. 예습, 수업, 교재 보강, 외부 보강을
서로 교수님 설명처럼 섞지 않는다.

## 주차 확정 — 학교 LMS 먼저, 그다음 Notion

- 주차를 정하거나 새 Week 페이지를 만들기 전에 학교 LMS 과목의 주차별 모듈을 읽는다. 로그인된 Playwright 브라우저에서
  `<학교 LMS 과목 주소>` 페이지를 열고 `tools/<lms>-modules.js`(SETUP.md로 만듦)를
  `browser_evaluate`로 실행한다(읽기 전용 GET). 과목 ID는 [workspace-map.md](../memory/workspace-map.md)에 있다.
- Notion Week N = 학교 LMS N주차 모듈이다. 한 주차에 덱이 여러 개이거나 한 덱이 두 주차에 걸칠 수 있으므로 항목 제목의
  슬라이드 범위(예: `<덱>-S01-11`, `S24-40`)로 나눈다.
- 그 표를 Notion 과목 페이지 목록과 대조해 빠진 주차, 범위가 어긋난 페이지, 번호 차이를 먼저 보고한다.
- 알고리즘 Q&A처럼 강의 다음 주에 진행하는 항목은 학교 LMS에 올라온 주차 번호를 그대로 쓴다(예: 5주차의 `QA - Week 5 - <주제>`는
  4주차 강의 내용의 Q&A).

## 강의 진도와 Supplementary (2026-10-08 사용자 정정)

- "내가 필기한 곳까지"는 **본문 진도**의 경계다. 마지막 필기 이후의 본문 슬라이드는 다음 주차에 나갈 내용이라 이번 Week에서 뺀다.
  교재 문제 범위도 이 본문 진도를 따른다.
- 진도 안의 슬라이드는 **필기가 없어도 전부 학습한 것**이므로 빠짐없이 정리한다(2026-10-08 사용자: "필기를 안 했더라도 거기까진 학습한거니까").
- 덱 끝의 Supplementary(Review·Ex·Exercise)는 **필기가 없어도 정리한다.** 진도 밖이라고 빼지 않는다. 각 항목은 주제가 맞는
  Week 페이지의 Supplementary·Ex 절에 넣는다(예: <덱> Ex-1~3 조건 코드·점프·분기 → Week 5, Ex-4·5 loop → Week 6).
- 필기가 없는 Ex의 답은 직접 풀고 재검산한다. 판단할 수 없으면 `⚠️ 확인 필요`로 남긴다.

## 교수님 자료와 필기의 신뢰도 (2026-10-01 사용자 확정)

- **교수님 강의자료는 쓰인 그대로 받아들인다.** C 표준·교재·일반론과 달라도 "표준에서는 UB", "단정밀도일 때만" 같은
  단서를 달지 않는다. 강의자료가 그렇다면 그렇게 안다.
- 교안 안에 오타나 자기모순이 있어도(예: 같은 행의 10진수와 16진수가 서로 다름) **교안에 쓰인 대로** 정리한다
  (2026-10-06 사용자 확정). 조용히 고치지 않고, 큰 정정 callout도 쓰지 않는다. 그 자리 바로 아래에 작게 접은 토글
  (`<summary>교안 참고</summary>`)로 문제만 알린다.
- **알고리즘 Q&A의 손글씨 답은 교수님이 수업에서 준 답이다**(2026-10-06 사용자 확정). 정답으로 취급하고, "다른 답도 가능",
  "답이 틀렸을 수 있음" 같은 메모를 페이지에 남기지 않는다. 교수님 풀이 흐름을 유지하고 보조 유도만 덧붙인다. 충돌을 찾으면
  사용자에게만 짧게 말한다.
- **사용자 필기본은 의심한다**(위 Q&A 답은 예외). 필기의 계산·용어·답은 전부 다시 확인하고, 틀리면 원래 값 → 올바른 값 → 이유 순으로
  그 자리에서 바로잡는다. 판독이 불확실하면 `[필기 판독 불확실]`로 남긴다.

## PDF와 TXT

- TXT는 인코딩과 줄바꿈을 확인하고 원문 범위를 보존한다.
- MarkItDown 추출문은 검색, 누락 탐지, 초안 작성에만 쓴다.
- 공식 PDF MCP는 페이지 이동·검색·스크린샷에 우선 사용하되, 도구가 반환한 페이지를 모델이
  실제로 확인했는지 점검한다. Codex에 해당 MCP가 없으면 `pdfinfo` + `pdftoppm`으로 렌더링한
  PNG를 직접 확인한다.
- PDF 모든 페이지의 시각 상태를 확인한다. 이미지 중심 자료나 손필기본은 1~3장씩 나눠 읽어
  실제로 보였는지 확인한다.
- 표, 그래프, 도식, 코드 정정, 손필기, 색 강조, 페이지 배치가 의미를 가지면 원본 렌더링을
  판단 근거로 쓴다. OCR과 추출문이 충돌하면 원본 화면을 우선한다.
- 강의에서 쓰는 기호, 풀이 순서, 용어, 슬라이드 순서를 더 예쁜 일반 해법으로 교체하지 않는다.
- 계산, 코드 출력, 수식, 정답은 직접 재검산하고 불확실하면 조용히 고치지 않는다.

## 강의 녹음 전사 TXT

- CLOVA Note·Whisper 같은 자동 전사문은 교수님 발화의 **근사치**다. 인용처럼 쓰지 않고
  `수업 녹음(자동 전사)`으로 출처를 표시한다.
- 전사 TXT는 속기록이다. **Notion 정리에는 같은 주차 강의자료(PDF·슬라이드)를 반드시 함께 쓴다.**
  강의자료의 구조·용어·순서를 뼈대로 삼고, 전사는 교수님의 설명·예시·강조를 해당 슬라이드 옆에
  보강하는 데 쓴다. 강의자료가 없으면 전사만으로 게시하지 말고 사용자에게 자료를 요청한다.
- 전문 용어·고유명사·수식·코드·숫자는 같은 주차 강의자료와 대조해 고친다. 자료로 확인할 수
  없는 오인식은 조용히 고치지 말고 `[전사 불확실: …]`로 남긴다.
- 화자 라벨(`참석자 1` 등)과 타임스탬프는 출처 추적에 쓰고, 본문에는 필요한 경우만
  `(녹음 12:34)` 형식으로 남긴다. 학생 질문은 교수님 설명과 구분한다.
- 잡담·출석·공지·반복 발화는 정리 대상에서 빼되, 과제·시험·마감 공지는 날짜를 지우지 말고
  별도로 표시한다.
- 전사 범위(시작·끝 시각, 누락 구간)를 `materials/index.md`에 기록하고, 게시 보고에 커버리지를
  적는다.

## 시험정보를 공부법에 반영하기 (2026-10-15 사용자 지시)

- 사용자 제공 과목 폴더의 족보는 **하위 폴더까지 재귀적으로** 찾는다. 복사·압축 해제 과정에서 수정 시각이 오래된 채로 들어올 수 있으므로 최근 수정 파일만으로 새 자료를 판단하지 않는다. 파일명이 깨졌으면 내부 표지·머리말로 시험 연도·학기·중간/기말·Part를 확인하고, 원본 해시와 경로를 기록한다.
- 새 수업 사진·문풀 기록·시험 공지·기출·수강 후기가 들어오면 먼저 **확인된 출처와 시험 시기**를 분리한다. 현재 수업·공식 공지가 범위와 형식의 기준이고, 과거 기출은 유형의 근거, 에타 후기는 연습 우선순위의 참고 자료다. 다른 학기나 중간·기말의 작품·진도를 올해 시험 범위로 옮기지 않는다.
- 새 학습 정리는 실제 유형에 필요한 행동(답 가리고 재풀이, 영어 단답 작성, 근거 인용, 계산·코드 손풀이, 오답 재검산)을 해당 개념 옆에 연결한다. 이미 게시한 Week·Q&A·기출 답안 본문은 시험정보 때문에 자동 재작성하지 않는다. 사용자가 별도 시험대비 페이지를 요청하면 과목의 `학습 도구` 아래 고유 키 `(과목 부모 ID, 학습 도구, 시험대비 정리)`로 찾아 필요한 부분만 갱신한다.
- 사용자 지정 원본에 `유형만 확인` 범위가 있으면 문항 풀이·정답을 만들지 않는다.

## 캡처

- 이해에 실제로 도움이 되는 영역만 자른다. 글만 있는 슬라이드는 가능한 한 native text로 쓴다.
- 파일명은 `<source-id>-pNNN-<slug>.png`로 한다. 슬라이드 번호가 PDF 페이지와 다르면 둘 다
  `materials/index.md`에 기록한다.
- **이미지 아래에 캡션·출처·`source:` 키를 쓰지 않는다**(2026-10-05 사용자 확정: 짧은 캡션과 접힌 출처 토글도 두지 않고 전부 삭제). 이미지는
  관련 설명 문장 바로 아래에 그냥 둔다. 출처(자료명·PDF 쪽·slide·source id)는 로컬 `materials/index.md`와 업로드 표(`uploads*.json`)에만 남기고,
  Notion에서는 이미지 파일명(`name=<source-id>-pNNN-<slug>.png`)과 페이지 상단 📘 자료 callout이 출처를 대신한다. 재실행 매칭 키도
  이 이미지 파일명 + 로컬 업로드 표다. Q&A 원본 쪽 전체 캡처도 캡션 없이 두고, 어느 문항 묶음인지는 바로 앞 문장에서 말한다.
- 캡처는 관련 설명 바로 아래에 둔다. 페이지 끝에 이미지 묶음으로 몰지 않는다.
- 실제로 보지 못했거나 업로드가 확인되지 않은 이미지를 반영했다고 보고하지 않는다.
- 같은 대상 페이지에서 이미지 파일명(`source_id + PDF page + crop slug`)이 로컬 업로드 표와 같으면 재업로드하지
  않는다. 하나의 키가 여러 이미지에 매칭되면 중단하고 확인한다.

## 교재 문제

- 강의 범위에 해당하는 교재 절의 문제는 **빠짐없이 전부** 문제은행에 넣는다(CS:APP Practice·Homework, CLRS 연습문제·장
  문제). 문제에 그림·도표·그래픽이 있으면 교재 PDF에서 잘라 캡처로 넣는다. 절차는
  [build-textbook-problem-bank](../skills/build-textbook-problem-bank/SKILL.md).

## 게시 전후

- 새 페이지보다 기존 canonical 페이지 업데이트를 우선하고 중복 제목·주차·작품을 검색한다.
- 작업 시작 전(게시 직전이 아니라 처음에) Notion의 과목 `AI 활용 문서`를 live fetch해 전부 읽고, 대표 기존 페이지도
  fetch한다. 게시 직전에는 최종 수정 시각만 다시 확인한다([course-ai-docs.md](course-ai-docs.md)).
- 게시 후 페이지를 다시 fetch해 섹션 순서, 원문, 수식, 이미지·캡션, 링크와 누락을 확인한다.
