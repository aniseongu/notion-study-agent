# Notion 작성 형식

이 문서는 사용자가 별도 형식을 주지 않았을 때의 기본값이다. 기존 페이지나 데이터베이스에
자체 템플릿이 있으면 그 형식을 우선한다.

강의·학습 노트는 이 일반 기본값보다 [style-profile.md](../memory/style-profile.md)와 해당 과목의
live Notion `AI 활용 문서`를 우선한다(작업 전 전문 fetch 의무: [course-ai-docs.md](course-ai-docs.md)). 과목별 자료 범위·페이지 구조는 과목 문서가, 공통 한국어
말투는 공통 말투 블록이 기준이다.

## 기본 원칙

- 제목은 검색 가능한 고유 명사를 앞에 두고, 내용이 드러나는 짧은 문장으로 쓴다.
- 첫 부분에는 2~4문장의 요약을 둔다.
- 사실, 결정, 할 일, 근거를 섞지 않고 구분한다.
- 할 일에는 가능한 경우 담당자, 기한, 상태를 연결한다. 값을 추측하지 않는다.
- 출처가 있으면 원본 URL이나 관련 Notion 페이지를 링크한다.
- 이미 관련 페이지가 있으면 새 페이지를 만들기보다 연결하거나 기존 페이지를 갱신한다.
- 과도한 이모지, 장식용 구분선, 중복 요약은 쓰지 않는다.

## 긴 학습 페이지의 가독성 (2026-10-16 조사)

- **읽는 경로를 먼저 준다.** 첫 callout은 시험 범위·목적처럼 바로 필요한 정보만 담고, 긴 본문은 `##` 큰 주제 → `###` 주차·개념군으로 나눈다. 목차는 제목을 따라 자동 갱신되므로 긴 페이지의 앞부분에 둔다. 기존 과목 관례가 접는 목차라면 이 문서 아래의 여러 줄 `<details>` 형식으로 감싼다. 핵심 강의 설명은 과목 `AI 활용 문서`가 요구하는 대로 펼친 본문에 둔다.
- **한 블록에는 한 판단 단위를 둔다.** 정의·사례 단서·예외를 서로 다른 개념과 한 문단에 과하게 뭉치지 않는다. 반복되는 비교는 짧은 불릿으로, 셋 이상의 대응 관계는 표로 묶는다. 인물·학파 암기표에는 확인된 올바른 짝만 적고, 잘못된 개인 TXT 연결을 그대로 재인용하지 않는다. 객관식 문제의 오답 선택지는 문제 형식이므로 이 규칙의 대상이 아니다.
- **접기는 탐색과 정답에 쓴다.** 목차·힌트·정답은 토글로 감싸고 요약 라벨에 무엇을 열게 되는지 적는다. 주차별 핵심 설명 전체를 일괄 접으면 훑어보기 어려우므로 과목 문서의 본문 공개 기준을 따른다. 강조 callout·색은 시험 정보나 실제 충돌처럼 주의를 바꿔야 하는 곳에만 쓴다.
- **시험 직전에는 짧은 회상 경로를 둔다.** 학습 가이드의 끝에는 주요 용어를 가리고 판정하는 짧은 확인 목록을 둔다. 강의 출처와 연습 문제는 해당 개념 가까이 연결한다. 데스크톱의 여러 열은 모바일에서 세로로 쌓이므로 긴 암기 페이지는 단일 열을 기본으로 한다.
- **근거와 적용 범위:** [Notion 공식 제목·목차·표·모바일 열 안내](https://www.notion.com/help/columns-headings-and-dividers), [Notion 공식 callout 안내](https://www.notion.com/help/customize-and-style-your-content), 공개 소스 [TheLobbi Notion Mastery의 접는 목차·강조 절제 패턴](https://github.com/TheLobbi/Claude-m/blob/main/notion/skills/notion-mastery/SKILL.md), [Jellypod 학습 가이드의 용어표·주제군·접힌 답·압축 회상 구성](https://github.com/Jellypod-Inc/school-skills/blob/main/skills/lecture-to-study-guide/SKILL.md), [jsoehner Notion Knowledge Capture의 보조 자료 접기·본문 블록 구분](https://github.com/jsoehner/skills-backup/blob/main/skills/notion-knowledge-capture/SKILL.md)을 2026-10-16 확인함. 오픈소스 예시는 아이디어 근거이고 현재 사용자 지시·과목 live `AI 활용 문서`·실제 Notion 렌더링 검증이 우선임.

## 속성 값

- 상태와 select 값은 기존 옵션의 정확한 철자를 사용한다.
- 빈 값을 임의의 `Unknown`, `기타`, `미정`으로 채우지 않는다. 스키마가 요구하면 사용자에게
  확인하거나 recipe에 정의된 기본값만 쓴다.
- 날짜만 아는 경우 임의 시간을 추가하지 않는다. 시간이 있으면 시간대까지 보존한다.
- 사람 속성은 이름 문자열이 아니라 현재 workspace에서 확인된 사용자 객체로 연결한다.

## 학습 노트 문체

- 같은 수업을 먼저 이해한 대학생이 정리한 정보글처럼 짧고 직접적으로 쓴다.
- 존댓말 안내체, 친한 척하는 챗봇 문장, `결론부터 말하면` 같은 고정 도입을 반복하지 않는다.
- `~임`, `~됨`, 질문형, 완결된 설명문을 섞되 같은 어미를 세 문장 연속 반복하지 않는다.
- 제목만 읽어도 실제 개념과 비교 대상이 드러나게 한다.
- 가벼운 커뮤체·욕설·밈은 시험 함정이나 오개념을 정확히 기억시키는 경우에만 쓰고 사람·집단을
  향하지 않는다. 쓸 표현은 [meme-dictionary.md](../memory/meme-dictionary.md)에서 고르고, 확인일이 30일 지난 밈은
  다시 검색해 갱신하기 전에는 쓰지 않는다. 사용자가 욕설 사용을 허용했다(2026-10-05).
- 영어 원문, 문제, 선택지, 코드, 수식, 인용, 제출용 문장은 말투 때문에 바꾸지 않는다.
- 정확성과 출처 구분이 말투보다 우선이다.

## Notion 본문 표기 — 깨지는 글자·수식 금지 (2026-10-05 사용자 지시, 재발 방지)

사용자가 `&gt;` 같은 알아볼 수 없는 글자와 렌더링이 불확실한 수식을 보고 "다시는 쓰지 말라"고 지시했다. Notion에 올리는 모든 본문(주차 페이지, 문제 페이지, 보강 글)에 적용한다.

1. **HTML 엔티티 금지.** `&gt;`, `&lt;`, `&amp;`, `&nbsp;` 같은 글자를 본문·표 셀에 쓰지 않는다. 비교 기호·`&`·`|`·`^`·`~`가 필요하면 **코드 스팬(백틱)** 안에 그대로 쓴다: `` `>` ``, `` `a & b` ``. 표 셀의 `Greater (Signed >)`는 `Greater (Signed `>`)`로 쓴다.
2. **수식은 단순한 것만, 형식은 `$`식`$`.** 인라인은 `$`x`$`(백틱을 끼운 형식), 블록은 `$$`만 있는 줄 사이. `$x$` 형식과 줄 안의 `$$…$$`는 금지.
   - 허용: `\frac`, `\sum`, `\log`, `^`, `_`, `\le \ge \ne`, `\times \cdot`, `\lceil \rceil \lfloor \rfloor`, `\Theta \Omega \omega`, `\mathrm{}`, `\hat{}`, `\ldots`.
   - **금지:** `\operatorname`, `\mathbin`, `\widehat`, `\text`, `\pmod`, `\left`/`\right`, `\begin{cases|aligned|array}`, `\\[3pt]`, `\substack`, 이중 이스케이프(`\\frac`). 경우를 나누는 식은 문장으로 풀어 쓴다("0 ≤ p ≤ k−2일 때 …, p ≥ k−1일 때 …"), `mod`는 `\mathrm{mod}`나 문장으로.
   - **비트 연산·어셈블리·C 표현은 수식이 아니라 코드 스팬이다.** `x ^ y`, `t & 1`, `~x`, `x >> 3`을 LaTeX(`\oplus`, `\mathbin{\hat{}}`)로 쓰지 않는다.
3. **글꼴 구분을 지킨다.** 명령어·레지스터·변수·C 코드·주소·16진수는 항상 고정폭(코드 스팬/블록), 수식은 수식 형식, 설명은 일반 글꼴. 같은 요소를 어떤 곳은 코드로, 어떤 곳은 일반 글자로 섞어 쓰지 않는다. 굵게·callout을 남발하지 않는다.
4. **게시 전 검사 필수.** `tools/lint-notion-content.py <본문 .md 또는 problem JSON 폴더>`가 0건이어야 쓴다(폴더는 하위 폴더까지 검사하고, 검사할 파일이 0개면 실패한다). 첫 페이지를 게시한 뒤에는 fetch 결과에서 `&…;` 잔여와 수식 이상을 눈으로 확인한다. Codex 초안·위임 패킷에도 이 규칙을 그대로 적는다.

## 종결어미·토글 형식 (2026-10-05 사용자 지적, 재발 방지)

1. **본문 서술은 커뮤체 종결 위주.** `~임`, `~됨`, `~함`, `~거임`, `~아님`, 짧은 단문, 질문형을 섞는다. 해라체 `~다`·`~한다`·`~이다`로 끝나는 서술문은 한 문단 안에서 연속 2개 이하, 페이지 전체 서술문의 30% 이하로 둔다(🎯 목표 불릿과 문제 원문 번역은 예외). 같은 종결 3연속 금지는 그대로다. 위임 패킷과 게시 전 점검(`tools/lint-notion-content.py --tone`)에 이 비율을 넣는다.
2. **접는 목차·토글은 여러 줄 형식으로만 쓴다.** `<details>`와 `<summary>`를 같은 줄에 붙여 쓰면 `\<details\>` 글자로 깨지고 목차가 접히지 않는다. 반드시
   ```
   <details color="gray_bg">
   <summary>📑 목차 펼쳐보기</summary>
   	<table_of_contents/>
   </details>
   ```
   형태(자식은 탭 들여쓰기)로 쓰고, 게시 후 fetch에서 `\<details` 잔여가 없는지 확인한다. 린터가 이 형식(같은 줄 금지·다음 줄 `<summary>`·여닫음 수·탭 들여쓰기·이스케이프 잔여)을 검사한다.
   DB 전체 점검: 대상 data source 안에서 Notion 검색 `details gray_bg summary`를 돌려 하이라이트에 `<details`가 보이는 행이 있으면 깨진 것이다(검색 색인은 수정 뒤 몇 분 늦을 수 있으니 최종 판정은 fetch).
3. **표 셀에 HTML 태그를 쓰지 않는다.** `<code>x</code>` 대신 백틱 `x`, 빈칸 `________`는 백틱 `____`(밑줄이 마크다운에서 줄어든다). 표 구조 태그(`table tr td`)와 `<br>`만 허용한다.
